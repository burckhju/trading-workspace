# v1.1.0 – Trade & Position

## Release

`v1.1.0-trade-position`

## Feature

FT-009 – Trade & Position / Purchase Execution Capture

## Scope

This release adds durable capture of warrant purchases that actually occurred and derives the current open position from the recorded purchase executions.

The feature records user-confirmed execution facts. It does not choose a purchase quantity, place broker orders or manage exits.

## Delivered capabilities

- Trade, ExecutionRecord and Position as separate domain concepts
- initial purchase from an existing FT-008 ProductSelection
- initial external purchase for an existing FT-004 warrant
- additional purchases for an existing trade
- immutable purchase execution history
- deterministic position aggregation
- weighted average entry price
- historic TradePlan, ProductSelection and ProductEvaluation provenance
- SQLAlchemy persistence and Unit of Work
- Alembic migration `20260817_0014`
- REST command API under `/api/v1/trade-position`

## API

Delivered endpoints:

- `POST /api/v1/trade-position/purchases/from-selection`
- `POST /api/v1/trade-position/purchases/external`
- `POST /api/v1/trade-position/trades/{trade_id}/purchases`

The purchase-capture flow intentionally minimizes user input.

## Deferred scope

The release does not include:

- sell executions or partial exits
- stop management
- trade-management events
- broker order lifecycle
- fees, commissions or taxes
- post-trade review

These remain follow-on scope, primarily FT-010 and later features.
